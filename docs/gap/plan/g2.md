# 🌿 G2 — Consumer Trust Layer: Full Implementation Plan

---

## Implementation Order

The 6 gaps form a layered consumer experience. Build from the entry point inward, because each layer adds depth to the passport:

```
Step 1 → Consumer QR Entry Point + Verification API Integration
Step 2 → Authenticity Verification Badge (instant trust signal)
Step 3 → Product Passport View (the main journey timeline)
Step 4 → Origin Story (map + farmer + harvest details)
Step 5 → Lab Certificate Display (scientific proof)
Step 6 → Recall Alert View (safety layer)
Step 7 → Share/Export Journey (virality + reach)
Step 8 → Full Consumer Integration Test
```

---

## STEP 1: Consumer QR Entry Point + Verification API

**What:** The mechanism by which a consumer enters the HerbChain ecosystem — either by scanning a product QR with their phone camera or by opening a deep link. No login required. No app install required for basic verification.

**Why first:** Every other G2 screen is downstream of this entry point. If the consumer can't get in, nothing else matters.

### 1A. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| Entry method 1 | In-app consumer scanner | For users who already have the HerbChain app installed |
| Entry method 2 | Web-based deep link | QR encodes a URL like `herbchain.in/verify/PROD-001` that opens a mobile web page — no app needed |
| Entry method 3 | Generic QR scanner fallback | If consumer uses their phone's default camera app, the QR URL opens in browser |
| API | `VerifyAPI.verifyProduct(productId)` | Fetches full product lineage, batch history, certifications, recall status |
| Data privacy | Backend returns a **consumer-safe projection** | Hides pricing, exact farmer name, internal IDs; shows only verification-relevant data |
| Caching | Cache verification result for 5 minutes | Avoid repeated API calls if consumer re-scans |

### 1B. Consumer-Safe Data Projection

This is critical. The backend must return a filtered view for consumers:

| Field | Visible to Consumer? | Example |
|---|---|---|
| Product name | ✅ Yes | "Ashwagandha Wellness Capsules" |
| Manufacturer name | ✅ Yes | "Himalayan Herbals Pvt Ltd" |
| Manufacturer license | ✅ Yes | "AYUSH License: AYL-2025-00123" |
| Batch count | ✅ Yes | "Made from 3 certified batches" |
| Farmer name | ❌ No (anonymized) | "Verified Farmer, Region: Rajasthan" |
| Farmer GPS exact | ❌ No (fuzzed) | Show district-level, not exact coordinates |
| Harvest date | ✅ Yes | "Harvested: March 2026" |
| Cultivation type | ✅ Yes | "Organic" |
| Lab name | ✅ Yes | "NABL Accredited Lab, Jaipur" |
| Test results summary | ✅ Yes | "Purity: Passed, Heavy Metals: Passed" |
| Full test data | ⚠️ Partial | Show pass/fail, not raw PPM values |
| Certificate | ✅ Yes (PDF link) | Downloadable certificate |
| Transfer timestamps | ✅ Yes | "Transferred: 15 Mar 2026" |
| Transfer pricing | ❌ No | Never exposed |
| Transporter name | ❌ No (anonymized) | "Verified Transporter" |
| Blockchain hash | ✅ Yes | "Verified on-chain: 0x3f2a..." |
| Recall status | ✅ Yes | "No active recalls" or "⚠️ RECALLED" |

```

- Return structured JSON with all verification data
- Include blockchain proof hashes for critical events
```

## STEP 2: Authenticity Verification Badge (Gap 2.2)

**What:** The very first thing a consumer sees after scanning — a large, unambiguous visual badge that instantly communicates whether the product is genuine.

**Why second:** Before the consumer reads any details, they need an instant trust signal. This is the "10-second understanding" requirement.

### 2A. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| Verification logic | Multi-factor check on backend | Not just "QR exists" but chain integrity |
| Badge rendering | Large animated component | Must be visually striking and impossible to fake |
| Factors checked | QR validity + chain completeness + lab certification + recall status + blockchain proof | All must pass for "Authentic" |

### 2B. Verification Logic — Multi-Factor Check

The badge is NOT simply "QR found in database." It checks five factors:

| Factor | Check | Pass Condition |
|---|---|---|
| 1. QR Validity | Is the product QR active and unexpired? | QR exists and status = ACTIVE |
| 2. Chain Completeness | Does the product have an unbroken ownership chain? | Every batch has Farmer → Transporter → Lab → Transporter → Manufacturer |
| 3. Lab Certification | Are all linked raw batches lab-certified? | Every batch has at least one PASSED certificate |
| 4. Recall Status | Is the product or any linked batch under recall? | No active recalls on product or any batch |
| 5. Blockchain Proof | Do the critical events have blockchain anchors? | BATCH_CREATED, OWNERSHIP_TRANSFERRED, LAB_CERTIFIED all have on-chain hashes |

**Badge outcomes:**

| Score | Badge | Color | Message |
|---|---|---|---|
| 5/5 | ✅ AUTHENTIC | Green | "This product is fully verified and authentic" |
| 4/5 | ⚠️ MOSTLY VERIFIED | Yellow | "Product verified with minor gaps in documentation" |
| 3/5 | ⚠️ PARTIALLY VERIFIED | Orange | "Some verification steps are missing" |
| ≤2/5 | ❌ SUSPICIOUS | Red | "This product could not be fully verified. Exercise caution." |
| 0/5 or QR invalid | ❌ COUNTERFEIT | Dark Red | "This product is not registered in the HerbChain system." |

## STEP 3: Product Passport View (Gap 2.1)

**What:** The main journey timeline showing the complete path of the product from farm to shelf, including all linked raw batches.

**Why third:** Now that the consumer trusts the badge, they want to see the story behind it.

### 3A. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| Data source | `VerifyAPI.verifyProduct()` from Step 1 | Already returns full lineage |
| Timeline rendering | Vertical timeline component | Standard UX for supply chain journeys |
| Multi-batch handling | Collapsible batch groups | Consumer sees product-level first, can drill into individual batches |
| Anonymization | Applied at API level | Frontend never receives raw sensitive data |

### 3B. Information Architecture

The passport has three levels of depth:

```
Level 1: Product Overview (what the consumer sees first)
  ├── Product name, manufacturer, license
  ├── Authenticity badge (from Step 2)
  ├── "Made from X certified batches"
  └── Total journey duration (e.g., "45 days from farm to shelf")

Level 2: Journey Timeline (scroll down)
  ├── 🌱 Farm Stage (aggregated across all batches)
  ├── 🚛 Transport Stage 1
  ├── 🔬 Laboratory Stage
  ├── 🚛 Transport Stage 2
  ├── 🏭 Manufacturing Stage
  └── 📦 Finished Product

Level 3: Batch Detail (tap any stage to expand)
  ├── Individual batch IDs (anonymized)
  ├── Specific dates and locations
  ├── Lab test results for that batch
  └── Blockchain proof for that event
```
