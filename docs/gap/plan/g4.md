# 🌿 G4 — Visualization & Intelligence: Full Implementation Plan

---

## Implementation Order

G4 transforms raw data into visual, actionable intelligence. Build from the most-used features outward:

```
Step 1 → Documents Center + Upload UI (foundational for all roles)
Step 2 → Shipment Map View (live tracking — highest visual impact)
Step 3 → Harvest Location Map (consumer + admin origin visualization)
Step 4 → Blockchain Proof Display (cross-cutting trust component)
Step 5 → Route History (extends shipment map with historical data)
Step 6 → Document Verification (extends documents center with authenticity)
Step 7 → Geofence Alerts (most complex — needs map infrastructure from Steps 2-3)
Step 8 → Full Visualization Integration Test
```

---

## STEP 1: Documents Center + Upload UI (Gaps 4.5, 4.6)

**What:** A centralized hub where every role can view, upload, and manage documents linked to batches, shipments, and products. This includes lab certificates, invoices, proof-of-delivery images, compliance documents, and farmer registration papers.

**Why first:** Documents are the most universally needed feature across all roles. Backend Phases 10 (Documents) and 17 (Uploads) are already complete — the API exists, the storage exists, but there is zero UI. Every other G4 step references documents in some way.

### 1A. Current State vs Target State

| Aspect | Current | Target |
|---|---|---|
| Document storage | Backend Phase 10 + 17 complete | Cloud storage with pre-signed URLs |
| Document metadata | Stored in DB (140+ models include documents) | Linked to batches, shipments, products, users |
| Upload UI | None | Role-specific upload flows |
| Document viewer | None | In-app PDF/image viewer |
| Document search | None | Search by batch, type, date, role |
| Document verification | None | Hash check against blockchain |

### 1B. Document Types by Role

| Role | Document Types They Upload | Document Types They View |
|---|---|---|
| **Farmer** | Farm registration, land records, organic certification, harvest photos | Transfer receipts, payment confirmations |
| **Transporter** | Proof of Delivery (POD) photos, vehicle registration, driver license, trip sheets | Pickup confirmations, shipment manifests |
| **Lab** | Test reports, certificates (PDF), calibration records, analyst signatures | Batch registration forms, farmer declarations |
| **Manufacturer** | Manufacturing licenses, GMP certificates, product formulations, batch records | Lab certificates, transport PODs, farmer declarations |
| **Admin** | Regulatory circulars, compliance notices, audit reports | ALL documents across the ecosystem |
| **Consumer** | None (read-only) | Lab certificates, product passports |

### 1C. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| File picker (mobile) | `expo-document-picker` + `expo-image-picker` | Handles PDFs, images, and camera captures |
| File upload | Multipart form data to backend | Backend Phase 17 handles S3/cloud storage |
| File preview (mobile) | `expo-file-system` + `react-native-pdf` for PDFs; `Image` for photos | Native rendering, no external app needed |
| File preview (web) | `<iframe>` for PDFs; `<img>` for images | Browser-native, no plugins |
| Max file size | 10MB per document | Configurable on backend |
| Supported formats | PDF, JPG, PNG, WEBP | Covers certificates and photos |
| Metadata | Auto-captured: uploader, timestamp, GPS, linked entity | Backend Phase 10 schema |

## STEP 2: Shipment Map View — Live Tracking (Gap 4.1)

**What:** A real-time map showing the current location of active shipments as they move from origin to destination. Available to transporters (their own shipments) and admins (all shipments).

**Why second:** The backend already captures GPS data at every transfer and during transit (Phase 4: Shipments+GPS+POD). This data is currently invisible. A live map is the most impactful visualization HerbChain can offer.

### 2A. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| Map library (mobile) | `react-native-maps` (Expo compatible) | Industry standard, supports markers, polylines, regions |
| Map library (web) | `react-leaflet` with OpenStreetMap tiles | Free, no API key, works globally |
| Location updates | GPS pings every 5 minutes during active shipment | Balances accuracy with battery/data usage |
| Data source | `ShipmentsAPI.location(shipmentId)` | Returns latest GPS + historical pings |
| Marker styling | Role-colored markers (green=transporter, blue=admin view) | Visual differentiation |
| Auto-refresh | 30-second polling for active shipments | Near-real-time without WebSocket complexity |

### 2B. GPS Data Flow (Already Built in Backend)

```
Transporter App (during active shipment)
  ↓
  GPS ping every 5 minutes
  ↓
  POST /api/shipments/:id/location
  Body: { lat, lng, timestamp, speed, heading }
  ↓
  Backend stores in ShipmentLocation table
  ↓
  Map view fetches: GET /api/shipments/:id/locations
  ↓
  Returns array of { lat, lng, timestamp } points
```

## STEP 6: Document Verification (Gap 4.7)

**What:** The ability to verify that a document (certificate, report, license) is authentic and has not been tampered with, by comparing its hash against the blockchain record.

**Why sixth:** Extends the Documents Center from Step 1 with a trust layer. Works hand-in-hand with the Blockchain Proof Display from Step 4.

### 6A. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| Hash algorithm | SHA-256 | Industry standard for document integrity |
| Hash storage | Computed on upload, stored in DB + blockchain | Backend Phase 10 already supports this |
| Verification | Re-compute hash of current file → compare with stored hash | Any modification changes the hash |
| Visual indicator | Green checkmark (verified) / Red X (tampered) | Instant trust signal |

   "This document is authentic and unmodified."

## STEP 7: Geofence Alerts (Gap 4.4)

**What:** Automated alerts triggered when a shipment deviates from its expected route or enters/exits predefined geographic zones.

**Why seventh:** Most complex G4 feature. Requires the map infrastructure from Steps 2-3 and the notification system from G1.

### 7A. Technical Approach

| Item | Choice | Reason |
|---|---|---|
| Geofence definition | Admin draws zones on map or sets radius around waypoints | Flexible for different route types |
| Detection | Backend compares GPS pings against geofence polygons | Server-side detection, not client-side |
| Alert types | Route deviation, zone entry, zone exit, prolonged stop | Covers all anomaly scenarios |
| Severity | Configurable per geofence | Critical (restricted zone) vs Warning (minor deviation) |
| Notification | Push to admin + transporter | Real-time alert via G1 notification system |

### 7B. Implementation Tasks

**Task 7.1 — Build Geofence Management page (web)**
```
Location: website/src/pages/GeofenceManagement.jsx

Features:
1. Map interface for drawing geofences
   - Draw polygon around expected route corridor
   - Set radius around origin/destination
   - Define restricted zones (e.g., "shipment should NOT enter this area")

2. Geofence Rules
   - Rule 1: "Shipment must stay within 10km of Route A"
   - Rule 2: "Alert if shipment stops for >1 hour outside designated stops"
   - Rule 3: "Critical alert if shipment enters restricted zone X"

3. Active Geofences List
   - Name, type, associated routes, alert count, status
   - Enable/disable toggle

4. Alert History
   - All geofence-triggered alerts with timestamps
   - Link to shipment and route history
```

**Task 7.2 — Build backend geofence detection**
```
Location: Extend Backend Phase 4 (Shipments+GPS)

Logic:
- On each GPS ping from active shipment:
  1. Check if point is within expected route corridor
  2. Check if point is inside any restricted zone
  3. Check if shipment has been stationary outside designated stops
  4. If violation detected:
     a. Create geofence alert record
     b. Send notification to admin
     c. Send notification to transporter
     d. Log to compliance system (G3)
     e. Anchor alert to blockchain
```
